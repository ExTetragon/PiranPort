# 3.2.4 弹药物品实现方案

> 2026-10-26。0.1.102已实现八种弹药物品、逐弹种制造点数及现有体系接入，移除旧通用注册和物品悬浮说明。生产线已在0.1.103接入，战斗未实现；物品阶段验证见第9节。
> 分类依据为[策划书](策划书.pdf)第3.2.4节；制造体系参考[船坞方案](3.2.2-船坞-实现方案.md)和[开发工厂方案](3.2.3-开发工厂-实现方案.md)，核心库存参考[舰装核心方案](2.1.1-舰装核心-实现方案.md)。本文只规定弹药物品；生产线设施、费用、耗时及GUI规则已在[弹药生产线方案](3.2.4-弹药生产线-实现方案.md)实现，生产线规则及当前验证见该文档。

## 1. 范围与注册

弹药为普通消耗品，分为四类、八个具体弹种。八个弹种分别注册独立物品，共用`item/AmmunitionItem`实现；身份直接由物品注册ID决定，不通过组件或自定义名称判断。

下表ID均属于`piranport`命名空间；每种物品的堆叠上限均为64。

| 类别 | 中文名 | 英文名 | 注册ID | 制造点数／枚 | 满叠点数 |
|---|---|---|---|---:|---:|
| 炮弹 | 高爆弹 | High-Explosive Shell | `high_explosive_shell` | 2 | 128 |
| 炮弹 | 穿甲弹 | Armor-Piercing Shell | `armor_piercing_shell` | 3 | 192 |
| 炮弹 | 防空弹 | Anti-Aircraft Shell | `anti_aircraft_shell` | 3 | 192 |
| 深水炸弹 | 深水炸弹 | Depth Charge | `depth_charge` | 1 | 64 |
| 鱼雷 | 直航鱼雷 | Straight-Running Torpedo | `straight_running_torpedo` | 3 | 192 |
| 鱼雷 | 制导鱼雷 | Guided Torpedo | `guided_torpedo` | 4 | 256 |
| 导弹 | 反舰导弹 | Anti-Ship Missile | `anti_ship_missile` | 8 | 512 |
| 导弹 | 防空导弹 | Anti-Aircraft Missile | `anti_aircraft_missile` | 6 | 384 |

`depth_charge`即“深水炸弹”，沿用现有注册ID；它是弹药，与武器装备`depth_charge_projector`（深弹投射器）分别注册。

现有`main_gun_ammunition`、`torpedo`、`missile`三个通用弹药注册由具体弹种替代，不另行保留为第九种及以后的弹药。内部测试使用新存档，不增加旧ID转换、别名注册或迁移分支。

## 2. 物品状态与默认行为

- 八种弹药无耐久、燃油、装备型号、弹种数据组件或随机UUID；不增加单枚可变状态。
- 普通`/give`、创造栏及合法产物创建直接得到对应弹种，不需要初始化身份或修复缺失组件。
- 改名不改变弹种、类别、制造点数或准入规则；不同弹种不能合并堆叠。同种弹药沿用原版物品及组件相同时才能堆叠的规则。
- 保留原版自定义名称等组件的正常保存、同步和容器转移行为。无专用身份组件不意味着可以丢弃已有原版组件。
- 不增加右键发射、放置、库存爆炸、掉落保护、无限寿命或自动消耗效果，沿用普通物品行为。
- 不为弹药增加装备属性修正，不参与核心武器／设备栏的属性汇总。

## 3. 共用分类定义

跨系统分类归入`domain/ammunition/`，用简单枚举表达四个类别和八个弹种。每个弹种关联所属类别，并在弹种定义中保存固定制造点数；类别只负责分组，不统一规定点数。物品、GUI和扣料逻辑读取同一份弹种定义，避免重复维护。

`AmmunitionItem`持有弹种定义，查询弹种、类别和点数时读取固定定义，不把这些字段重复写入`ItemStack`。领域定义不依赖具体物品注册、方块、菜单、客户端类或事件实现；物品注册负责将定义与具体物品关联。

固定弹种身份不从可重载标签推导。标签变化可以改变物品是否准入某个库存，但不能把穿甲弹变为鱼雷。共用分类文本继续归`text/`，显示时不以中文、英文名称或枚举顺序充当身份键。

本阶段不添加国籍、口径、武器适配列表、伤害、穿甲、制导精度、引信、爆炸半径或一次开火的耗弹量。未来战斗规则另行定义，不预设零值功能参数。

## 4. 物品标签与核心弹药库

保留总标签`piranport:ammunition`，增加四个类别子标签，由总标签引用子标签：

| 子标签 | 收录弹种 |
|---|---|
| `piranport:ammunition/shells` | 高爆弹、穿甲弹、防空弹 |
| `piranport:ammunition/depth_charges` | 深水炸弹 |
| `piranport:ammunition/torpedoes` | 直航鱼雷、制导鱼雷 |
| `piranport:ammunition/missiles` | 反舰导弹、防空导弹 |

标签规则由`datagen/tags/ModItemTagsProvider`生成，资源位于`data/piranport/tags/item/`。不为每个独立物品再创建仅含自身的标签，也不把本模组弹药分类擅自放入未确认的`c:`公共标签。

核心弹药库继续按总标签准入，八种弹药均可按64堆叠存放。不要求先装备对应发射器，不要求图纸许可，不增加个人解锁、弹药图纸或许可收集进度。

弹药不加入武器、飞机或设备标签，不进入对应装配栏。核心通用仓库仍按既有规则存放普通物品；存放弹药不会增加核心属性。

数据包／标签变化后，不再符合准入条件的既有库存仍保留并允许抽取，不清空、不截断。库存查询返回副本，写回及模拟行为沿用核心现有规则。

### 4.1 与制造设施的准入区别

核心弹药库与制造设施保持不同职责：

- 核心弹药库按`piranport:ammunition`判断存放资格。
- 船坞和开发工厂同时要求总标签准入及有效的正数制造点数。
- 第三方普通物品仅加入总标签，可以取得核心存放资格，但不会自动获得制造点数。无点数的物品不能被制造设施按免费材料或任意默认值消耗。

本阶段不新增第三方点数配置、通用材料接口或按标签猜测点数的行为。

## 5. 船坞与开发工厂的制造折算

八个弹种全部作为通用制造材料，依第1节分别提供2、3、3、1、3、4、8、6点，不排除贵重弹种。制造点数表示材料折算价值，按弹种的材料投入和制造复杂度分档；它是固定定义，不随数据包生产配方或实际制造成本自动重新计算。

船坞和开发工厂继续共用`blockentity/manufacturing/ManufacturingMaterials`：

1. 按缓存栏位从左到右、从上到下消耗；不改变现有顺序。
2. 不寻找最省组合，不按价格、弹种、点数或是否制导重新排序。
3. 按整枚扣除，最后不足一枚时向上取整，不找弹药零头。
4. 保留现有配方的弹药点数费用及4的倍数校验，不因拆分弹种而重定价。
5. 查询、预计扣料和模拟在副本上计算；失败开工不修改输入。
6. 取消返还开工实际扣除的原始弹种、数量及组件，不统一折算为高爆弹，也不把超额投入改为净点数退款。

例如需求4点，缓存顺序为深水炸弹1个、高爆弹2个，则实际消耗5点；取消返还上述3个原物品。单独使用穿甲弹时需要2个，实际投入6点；单独使用反舰导弹时需要1个，实际投入8点。配方费用为4的倍数不代表混投或高点数弹药一定没有超额投入。

贵重弹药也按上述规则消耗，不设置保留标记、优先级或额外确认。制造点数不表示战斗伤害、武器适配或一次开火的耗弹量。

需求48点且只使用一种弹药时，高爆弹消耗24个，穿甲弹、防空弹或直航鱼雷各消耗16个，深水炸弹消耗48个，制导鱼雷消耗12个，反舰导弹消耗6个，防空导弹消耗8个。

生产配方仅使用铜、钢、铝和火药，定稿数值见[生产线方案第2节](3.2.4-弹药生产线-实现方案.md#2-八项生产配方)。比较成本时核对每点制造价值的原料投入，不能只比较单枚。生产配方调整不自动改变本节定稿点数；若需变更点数，单独修改弹种定义及本方案。

## 6. 物品与制造界面的显示

### 6.1 弹药物品悬浮

八种弹药均不添加本模组专用悬浮说明，不显示类别、制造点数、当前堆叠点数、用途或尚未实现的战斗效果。

原版物品名称、自定义名称、F3+H信息、其他组件和外部模组添加的提示保持原样。归属行仍遵循项目通用原版显示规则，不为弹药补齐、隐藏、去重或重新着色。

### 6.2 船坞与开发工厂

制造点数说明只在船坞和开发工厂的相关界面上下文提供，不回写为物品通用悬浮。材料缓存中的弹药槽可在正常物品提示基础上附加：

```text
制造材料量：2 点/枚
当前堆叠：128 点
```

示例为一叠64枚高爆弹；穿甲弹、防空弹等其他弹种按各自点数计算。实际内容按对应物品和当前枚数计算，支持中英文；点数说明不添加“炮弹／鱼雷／导弹”等类别行，不另列弹药类型说明。

材料需求区域保留所需点数、当前可用点数以及现有“需要×点，预计投入×点”的语义。显示、预计扣除和实际扣料必须读取同一套点数与缓存顺序规则。原版物品名称仍正常显示，不以类别文字替代具体名称。

界面追加提示只负责显示，不修改物品组件、材料、任务或库存。不得因为材料槽在船坞／工厂界面中出现，就把其他位置的弹药悬浮也改为带点数。

## 7. 创造栏与资源

八个弹种全部列入现有主创造栏，顺序为高爆弹、穿甲弹、防空弹、深水炸弹、直航鱼雷、制导鱼雷、反舰导弹、防空导弹。现有创造栏会收录普通注册物品，不增加型号示例或重复展示项。

每个弹种提供独立物品模型、中英文名称及可辨认的图标。当前保留深水炸弹原16×16占位图，其余七种为新绘制的32×32代码像素图，正式美术可后续替换。图标可共用类别轮廓，通过弹头形状、色带或其他结构区分；不同弹种不只依靠颜色区分。不自动沿用装备型号32×32改绘图的尺寸约束。

英文名称区分`Anti-Aircraft Shell`和`Anti-Aircraft Missile`，中文区分“防空弹”和“防空导弹”。分类中使用“炮弹”，不继续用旧物品名“主炮弹药”限制其未来适用武器。

移除被替代的通用弹药注册及失效模型、贴图、翻译和测试引用，保留仍被使用的资源；不遗留可获得的旧通用物品。

## 8. 实现落点与验证范围

| 位置 | 职责 |
|---|---|
| `domain/ammunition/` | 固定类别、弹种及逐弹种制造点数 |
| `item/AmmunitionItem` | 关联定义、提供纯查询；不添加通用物品说明 |
| `registry/ModItems` | 八种物品注册；不提前解引用延迟注册项 |
| `registry/ModItemTags`、`datagen/tags/ModItemTagsProvider` | 总标签和四个类别标签 |
| `registry/ModCreativeTabs` | 现有主创造栏收录及排序 |
| `blockentity/manufacturing/ManufacturingMaterials` | 两制造设施沿用通用点数、缓存顺序、整枚扣除和原物退款 |
| `client/gui/screens/ShipyardScreen`、`DevelopmentFactoryScreen` | 仅在界面上下文显示点数说明 |
| `src/main/resources/assets/piranport/` | 八种模型、贴图、名称及界面文案 |
| `src/gameTest/`、`tools/verify_resources.py` | 注册、点数、标签、资源和接入回归 |

资源检查需要识别总标签引用子标签的结构，不能继续要求总标签直接列出四个旧ID。标签变化先修改provider，再运行数据生成并核对生成结果，不与手写资源占用同一相对路径。

验证覆盖以下行为：

- 八种物品唯一注册、默认有效、堆叠64、改名不改身份，不带专用身份、耐久或燃油状态。
- 四类别、八弹种与逐弹种点数2／3／3／1／3／4／8／6、满叠点数、中英文名称、模型与图标对应正确，创造栏无旧通用项或重复项。
- 总标签及四个子标签成员正确，核心弹药库准入、正常堆叠、标签变化后的保留抽取及副本写回正确。
- 八种弹药均能作为两制造设施的通用点数材料；缓存顺序、混投超额、纯查询、模拟和失败开工无副作用。
- 取消返还具体弹种、原始数量及组件，不以同点数的其他物品代替。
- 普通物品栏和创造栏不出现本模组弹药说明；两制造界面的弹药缓存槽显示正确点数且无类别行，原版提示不受影响。
- 船坞、开发工厂、日志及客户端GUI夹具中的旧弹药引用同步替换，原有回归语义保持有效。

实际实施时同步项目指引、参数表及实现状态，并按项目规则记录实际功能变更。方案文档本身不增加版本号或功能计数。
