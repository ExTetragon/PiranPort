## 已确认的生产规则

- 原料仅铜、钢、铝、火药四种，不接收铁或弹药作为生产原料。铜、钢、铝接受对应块、锭、粒，1块=9锭=81粒；火药按个计费，不用火药等价物替代。
- 补充铜粒物品及拆分／合并配方，1铜锭=9铜粒；铜块与铜锭沿用原版拆合。跨模组铜、钢、铝以对应公共材料标签识别，不创建专用内部旧格式兼容。
- 炮弹、深水炸弹一次加工产多枚；鱼雷、导弹一次产1枚。
- 数量控制只安排有限次数，不加入无限生产、持续模式、红石控制、动力或图纸。
- 每次实际开始加工时只扣本次材料，不锁定输入缓存，不提前扣后续次数的材料。
- 每完成一次，把本次全部产物存入输出缓存；旧产物可以保留，只要仍有足够空间。
- 输出空间不足时暂停，取走后继续。开始一次加工前应能容纳本次全部产物，而非仅能放入其中1枚。
- 不提供取消或主动退款。中断仅停止后续次数，当前已扣料的一次继续完成。
- 四侧允许输入原料与输出物品；下方只允许输出，顶部关闭。有可提取产物时禁止自动化抽原料，产物清空后才允许抽原料，GUI手动取原料不受此限制。四侧只能向原料缓存插入四种合法原料，产物缓存禁止外部插入。只安排有限计划，不增加外部自动开工、无限生产或红石控制；持续生产与远征整合后议。
- 工具匹配且正常采集时，仅将原料、产物缓存保存到方块物品，清除当前进度和后续任务，已投入本次的原料不退。工具不匹配时不掉方块，全部缓存物品散落，清除进度与任务，不退当前原料。当前一次尚未入库的内容不属于缓存。
- 创造拆除不掉机器，缓存全部散落；爆炸等不掉机器的移除同样散落缓存，当前投入不退。若正常战利品已将缓存存入机器，不再重复散落。
- 正常关闭GUI不停止生产；保存任务、进度和中断标记，区块重新加载后继续，不补算离线时间。拆除与卸载分开处理。
- 首次默认高爆弹、单次需求；完成整份计划或中断收尾时播放一次完成音，短周期逐批入库不连续播放。
- 配方四种费用均可为0但至少一项为正，单次产量与耗时为正；只用正费用计算材料上限，整份需求先安全计算再换算锭粒，拒绝溢出数量，不把0费用当作除数。

材料、产物已确定各8格，采用通用输出缓存，允许保留不同弹种。GUI布局为左侧分类和弹种按钮，中部单次材料与任务操作，右侧材料／产物缓存，底部玩家物品栏，无外置标签页和模型预览。

材料框左上显示当前模式标题“单次需求”或“总需求”，标题下方增加与船坞、开发工厂相同的分隔线，右上以18逻辑像素宽的两档开关切换，左档单次、右档总需求。材料行恢复图标和名称居左、数量居右；名称固定为铜材、钢材、铝材、火药。单次产量／时间、操作按钮、任务和进度文字仍居中。右侧保留输入／输出槽位和进度箭头，移除“材料缓存”“产物缓存”标题。

右栏顶部y=26居中显示“块锭粒可自动转换”，与单次产量／耗时同色（#A4BACB）。下方按输入槽组→进度箭头→输出槽组纵向排列，共用x=296中心线。槽组布局范围y=40–148，输入y=44–80、箭头y=84–104、输出y=108–144；上下和组间留白均为4逻辑像素。两组槽位宽72、高36，箭头宽高20，中心纵坐标依次为62、94、126。

任务下方的枚数、次数比例统一使用半角斜杠，两侧各一个半角空格，数字与中文单位紧邻，例如“16 / 40枚 · 第5 / 10次”。英文同样为“16 / 40 · Cycle 5 / 10”；中点两侧各一个半角空格。其他状态延续相同数字、单位和分隔规则。

金属需求按锭、粒自动换算，不显示块，只写非0单位：83粒显示9锭2粒，36粒显示4锭，4粒显示4粒。某种材料需求为0时整行隐藏，后续行紧凑上移，不显示0、不保留该行图标或名称。火药按个显示。未定稿费用暂用“—”，不列无依据的单位或数字。英文紧凑预览用i／n表示ingots／nuggets，需求悬浮只列当前模式和材料需求，不追加金属单位说明。

需求列表始终跟随当前浏览弹种；单次模式显示该弹种一次加工费用，总需求模式按左侧输入框／滑条枚数换算次数后计算。浏览其他弹种会更新列表；浏览目标、数量和所用配方不变时，生产进度及剩余次数变化不会改变需求数字。需求列表不锁定实际任务，不从总需求自动扣除已投入或已完成部分。

## 浏览状态的完整约束与核查

弹药生产线沿用船坞、开发工厂：每个打开窗口维护自己的临时浏览副本；最后一个关闭窗口的已应用浏览状态写回机器。机器仅保存这一份，任何玩家再次打开都读取它，不按玩家UUID保存或恢复个人选择。浏览不会改变共享任务，开工与中断由服务端统一处理。

保存弹药类别、所选弹种、单次／总需求模式；数量输入作为计划草稿记忆，但每次打开、提交和开工时重新按材料上限校正，不恢复任何已结束队列。拆除时按“仅保存缓存”清除浏览记忆，重新放置采用默认项。

2026-10-26核查：船坞和开发工厂菜单构造时均从机器取得浏览副本；浏览动作仅修改所在菜单；服务端关闭菜单时将该副本写回机器。两个方块实体均只持有一个remembered字段，通过Browse保存和恢复，没有按玩家身份索引的浏览表；浏览类复制不会共享可变状态。已有GameTest覆盖窗口互不干扰、后关闭覆盖、任意玩家重开、船坞NBT恢复；0.1.102的既有190项回归报告全部通过。本轮为源码和既有证据复核，未新增或重跑游戏验收；真实联网多人范围仍沿用既有人工验收边界。

## 本预览的数量口径

数量框文字居中，按总枚数展示，后台换算有限加工次数，不增加第二个次数输入框。炮弹、深水炸弹已确定每次4枚，步长4；鱼雷、导弹每次1枚，步长1。例如40枚高爆弹对应10次加工。

开工时的计划数量上限按现有材料计算：设本次产量为`q`，当前材料允许加工的完整次数为`B`，则数量上限为`M=q×B`。正数输入提交时向上修正到`q×ceil(N/q)`，再限制在`M`以内。例如输入5枚高爆弹修正为8枚；若只能再产4枚，则最多只能选择4枚，不能因向上修正而超预算。材料不足以完成一次时上限为0。空白、0和负数不能开工，回车或失焦后统一校正。服务端开工时重新检查当前材料，不信任客户端上限。

输入框已确定输入总枚数，再换算加工次数。有效单次产量与滑条步长、向上修正的倍数保持一致。

左侧输入框／滑条属于浏览草稿，与已开工计划分开；浏览弹种和数量可调整，不修改实际队列，材料框按草稿重新计算。实际任务数量在开工冻结，不随浏览草稿、缓存减少或生产进度自动缩减。图中任务正在加工第5／10次，已入库16／40枚。中断后不再启动第6次，当前第5次入库后结束，总计20枚。

产物空间不足图表示上一次已入库、第5次尚未扣料。此时中断可立即结束计划；如果已扣料的当前一次尚未成功入库，则中断仍需等待空间，完成这次入库后结束。

每次开始前重新规划原料扣除和整批产物空间；金属按粒→锭→块顺序消耗，同一规格按缓存槽位顺序。金属找零先回原料缓存，剩余部分尝试送入四侧相邻的可接收物品接口，仍有余量则在机器旁掉落；不因找零容纳问题停止生产，不将找零塞入玩家背包或产物缓存。相邻接口使用对向面能力，不强制加载区块，按实际插入后的剩余量继续处理，不在查询或模拟时掉落。

后续缺料时暂停等待补充，不减少剩余次数，不自动缩减计划。整份有限计划在开工冻结配方费用、产量、耗时，每次仍按快照重新计算当前缓存如何满足费用，不提前占用物品。开始前检查空间不等于锁定产物槽；如果有效标签或堆叠条件变化导致完工时不能入库，保留当前完成态并等待，不重复计时、扣料或生成。

## 定稿参数与实现状态

八项配方与机器、铜粒规则以[独立实现方案](../../3.2.4-弹药生产线-实现方案.md)及军工表为准。高爆弹一次4枚需3个火药，穿甲弹需2个；鱼雷／导弹为加强后的成本。旧单位示意图仅验证排版，不代表定稿费用。原先待确定的事务与GUI规则已并入方案，AL01–AL24的实际覆盖及人工边界见实现方案第12节。

实现时需区分可制造上限与浏览草稿：缓存变化只更新上限提示和可开工状态，不因当前任务逐次消耗而自动改写草稿数量；在主动提交数量或开工时重新校正。等待材料／下一次产物空间时，箭头不前进；当前一次已完成但尚未入库时保持完成进度，成功入库后才计入已完成枚数和次数，避免状态、计数不同步。

本目录仅保存设计预览与讨论口径，不表示生产线功能已经实现，也不改动现有船坞或开发工厂的布局。
