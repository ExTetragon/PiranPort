# 2.2 装备初步开发方案

> 2026-10-24。当前0.1.90：15个注册物品包含13类耐久装备的21个型号及2种普通消耗品，全部列入创造栏并可由开发工厂制造。快修／损管无身份和耐久，堆叠64／16；两个背包消耗配置默认关闭。装备无国籍。作战、航空、维修和自动消耗尚未实现，验证范围见第11节。
> 型号与字段见[装备参数表](舰装-装备.xlsx)；装配容器沿用[舰装核心方案](2.1.1-舰装核心-实现方案.md)，图纸沿用[蓝图方案](3.2.1-蓝图-实现方案.md)，制造事务参考[船坞方案](3.2.2-船坞-实现方案.md)。原始策划书保持原样。

## 1. 范围与当前边界

- 首批23项：10种武器、9种设备（包含2种消耗品）、4种飞机。维持15个注册物品，耐久装备按类别而非型号注册，快修与损管使用独立普通物品。
- 耐久装备不可堆叠，核心武器栏及普通设备每格1件；快修物品及设备栏上限64，损管上限16。消耗品堆叠例外已接入。
- 武器、普通设备、飞机具有装备耐久；飞机另存内部燃油。快修、损管无耐久，不增加内部状态、熟练度或强化。
- 武器、飞机及副炮作战参数留空，只留查询接口。雷达、声呐效果待设计；快修、损管不挂接作战配置或主动效果接口。
- 反舰／防空导弹细分合并，保留两个具体发射器型号；雷达取消对海／对空细分，原两个型号合为“先进型雷达”。这些历史用途名称不产生只能对海或只能对空的目标限制。
- 本阶段的属性接口只衔接核心已有的舰娘耐久、装甲、航速修正。三项属性修正均为0；最大装备耐久暂用250／1561／2031三档，飞机容量统一2000 mB，均为后续策划前的调试值。
- 船坞只产出没有预装武器的空核心。装备主要由开发工厂制造；奖励箱核心预装装备方案挂起。
- 维修规则后续单独设计。物品层与开发工厂已实现，维修界面和作战行为尚未实现。

## 3. 细分类别

| 适用类别 | 字段建议 | 值 | 用途 |
|---|---|---|---|
| 主炮 | `gunClass` | `SMALL`、`MEDIUM_LIGHT`、`MEDIUM_HEAVY`、`LARGE` | 四种炮级，供显示和未来超重判定；工厂不提供细分筛选 |
| 鱼雷发射器 | `torpedoUse` | `GENERAL`、`SUBMARINE` | 通用、潜用，属于并列用途 |
| 装甲 | `armorClass` | `SMALL`、`MEDIUM`、`LARGE` | 附加装甲的小型、中型、大型型号分类 |

装甲的“三种型号字段”采用一个三值分类，不使用三个可同时为真的布尔值。每个具体附加装甲型号具有唯一分类；将来同一分类可以增加不同型号。

导弹和雷达不设置用途细分字段，不在接口、提示或未来筛选中保留已取消的目标域分类。上游-1和MK-10仍是两个型号，后续可以有性能差异，但不按原作反舰／防空类别硬性限制可攻击目标。副炮保留独立作战接口，具体攻击方式留待后续。

细分类别从型号定义读取，不在每件物品中重复保存，不增加独立图纸许可。字段仅对适用类别存在，不给其他装备填造无意义的默认分类。序列化使用稳定文本 ID，不保存枚举序号。

核心仅按标签接收装备，不按炮级或舰种硬拒绝。适配、超重和数量限制由未来舰娘状态根据舰种与实际装配计算；不把“当前是否超重”保存为物品属性。具体承载阈值、负重点数与负面效果仍待讨论；策划书的“重型主炮”与这里“大型主炮／中型主炮（重）”的术语关系也需明确。

## 4. 型号定义与单件状态

### 4.1 耐久装备公共型号定义

本节字段适用于21个耐久装备型号。快修、损管作为普通消耗品，不要求填写本表中的耐久、修正或功能接口。

| 字段 | 类型／单位 | 约定 |
|---|---|---|
| `id` | 稳定资源 ID | 识别具体耐久装备型号；共21项；快修、损管为普通注册物品 |
| `category` | `EquipmentCategory` | 确认分组、注册物品、装配区域与许可 |
| 适用的细分类别 | 分类值 | 见第 3 节 |
| `translationKey` | 翻译键 | 如 `equipment.piranport.<型号路径>`，中英文名称均可检索 |
| `searchNames` | 不可变字符串集合 | 中英文、原作名和常见简称 |
| `modifiers` | `ShipStats` | 舰娘耐久、装甲、航速修正；当前全部0，允许后续负修正 |
| `maxDurability` | 正整数，装备耐久点 | 型号默认上限，创建时写入原版MAX_DAMAGE；调试值见第5.1节 |
| `fuelCapacity` | 非负整数，mB | 四类飞机均2000 mB，初始0 mB |
| 显示资源映射 | 资源 ID／型号映射 | 首批各型号用原作素材改造的 32×32 像素画，物品不重复保存贴图路径 |
| 功能接口 | 能力查询 | 本阶段没有作战配置和主动效果参数 |

“舰娘耐久修正”表示生命上限修正，不是装备自身耐久。装备不定义国籍字段；舰船国籍仅归`domain/ship/ShipNationality`，船坞继续使用舰R九组。

### 4.2 单件组件

| 内容 | 保存位置 | 约定 |
|---|---|---|
| 型号身份 | `piranport:equipment_identity` | 不可变型号 ID；不重复保存类别、细分和作战属性 |
| 最大装备耐久 | 原版 `MAX_DAMAGE` | 由型号默认值初始化，是原版耐久组件的上限 |
| 已损耗耐久 | 原版 `DAMAGE` | 剩余耐久 = 最大耐久 − 已损耗；不另存一份当前耐久 |
| 飞机内部燃油 | 复用 `piranport:fluid_content` | 不可变 `SimpleFluidContent`，保留流体及组件；仅接收本模组燃油 |

飞机除身份和型号参数外，只有耐久损耗、内部燃油两种单件状态。武器与设备不另设内部弹药、燃油、熟练度、强化或随机 UUID。舰娘核心的熟练度规则不受影响。

统一创建接口根据型号找到对应注册物品，初始化满耐久；飞机初始内部燃油为 0 mB。制造消耗的燃油是成本，不同时写入飞机油箱。普通 `/give` 不补型号；创建接口使用型号调试值初始化成品。

读取不会随机补型号。缺少身份显示“未初始化主炮”等类别名称，未知或跨类别身份保留可读取的原始内容并报告无效，不赋予有效功能。此类数据校验是当前物品有效性规则，不增加内部旧格式迁移。

### 4.3 接口边界

- 型号、分类、耐久、燃油和属性查询均无副作用。读取副本与修改后写回分开，不能修改核心查询副本后遗漏保存。
- `RiggingEquipment` 继续提供三项舰娘属性修正。只汇总实际武器栏、设备栏，仓库备用装备不产生收益；损坏装备不贡献属性。
- 武器、飞机、副炮只留作战能力查询入口，目前明确返回“未实现”，不填全零伤害、射速、射程等假配置，不触发攻击、自动发射或飞行。
- 雷达、声呐专属功能保留接口，范围、触发和冷却后续讨论。快修、损管不实现这些接口，未来消耗由舰娘状态统一处理。飞机暴露物品流体能力用于补油和取油；是否由核心供油及运行耗油规则尚未确定。损坏件仍可存取燃油，异常身份只允许抽取现存油。
- 客户端负责图标、按键、预览和文字；服务端负责身份、资源与状态校验，共用定义不加载客户端类。

## 5. 损坏与配置

已增加 COMMON 布尔配置 `retainBrokenEquipment`，中文名称为“是否保留耐久归零的损坏装备”，默认 `true`。名称、悬浮说明支持中英文，TOML 注释采用中英双语。不主动扫描或删除已有损坏件。

| 值 | 耐久耗尽时的行为 |
|---|---|
| `true` | 保留为损坏装备，剩余耐久 0，身份和飞机燃油保留；停止提供属性、攻击、探测及其他功能，可正常取出，留待未来维修 |
| `false` | 在耐久耗尽结算时销毁该件装备 |

使用原版耐久组件与耐久条；统一耗损接口 `EquipmentRules.damage` 和原版 `hurtAndBreak` 均应用保留规则。原版入口到达上限时保留DAMAGE=max，并阻止随后的回退和销毁。具体作战损耗事件、维修材料与修复量尚未确定，没有自动耗损。

切换配置仅影响后续实际耗损；读取、保存、复制和零损耗不销毁既有损坏件。配置false下，飞机随下一次耗损销毁时，内部燃油随物品消失。原版创造模式耗损入口保持免损；物品层接口不自行推断持有者。

### 5.1 暂用参数

参考固定版本原版 `Tiers` 的铁、钻石、下界合金耐久，暂分三档：

| 耐久 | 型号范围 |
|---|---|
| 250 | 神秘武器、小型附加装甲；0.1.83中的快修、损管也使用250，最新消耗品设计将移除它们的耐久 |
| 1561 | 中型轻／重主炮、两种鱼雷、刺猬弹、全部飞机、中型装甲、雷达、声纳、副炮 |
| 2031 | 两种大型主炮、两种导弹发射器、大型装甲、先进型动力系统 |

全部型号舰娘属性修正为0；四类飞机内部油箱均为2000 mB，初始0 mB。这些值是临时调试参数，不作为上限校验规则。

### 5.2 快修与损管消耗品

保留`piranport:quick_repair`、`piranport:damage_control`注册ID、名称与图标，改为两个普通物品，移出耐久装备型号定义。不保存`equipment_identity`、耐久、三项修正、作战配置或主动效果接口；普通give直接获得有效物品。无需为例外修改所有耐久装备定义或填入零值。

两者保留`piranport:devices`，另可加入`piranport:equipment_consumables`分类标签。快修物品及核心设备栏每格最多64个，损管最多16个；其他装配仍限1件。核心属性汇总直接跳过消耗品。创造栏各列一次，总展示条目仍为23。

开发工厂每次消耗1张图纸，产出8个快修或1个损管；快修整批800 mB燃油、32弹药点、8钢、8铝、5秒，损管800 mB、12点、6钢、4铝、15秒。

新增COMMON配置`allowQuickRepairFromPlayerInventory`、`allowDamageControlFromPlayerInventory`，中文分别为“是否允许直接消耗玩家背包中的快修”“是否允许直接消耗玩家背包中的损管”，均默认false，中英文名称／说明及双语TOML注释已接入。

未来优先消耗当前核心设备栏中的对应物品；没有可用物品时，分别按开关从该玩家快捷栏和主物品栏36格查找。不扫描副手、其他玩家或嵌套容器，不逐tick扫描。快修预期在受伤达到缺血阈值时消耗并回复生命，损管预期在死亡时消耗以抵消死亡。本阶段不实现触发，阈值、回复量、免死后血量、冷却及同次伤害顺序后续单独设计，不写入物品内部。

## 7. 创造栏、贴图与核心衔接

- 耐久装备名称按具体型号显示，改名不改变真实身份与图标。目标创造栏列21个有效型号及2种普通消耗品，不展示未初始化类别物品，每项一次。
- 创造栏耐久装备初始满耐久、飞机内部燃油0 mB，消耗品无单件内部状态；不另列损坏、不同油量或损耗阶段的重复条目。
- 各型号有独立图标与预览资源。模型选择参考核心的身份映射；未知身份回退类别图标，不把渲染编号保存成永久身份。
- 耐久装备提示将类别与细分合为一行：主炮·小型、主炮·中型（轻）、主炮·中型（重）、主炮·大型；鱼雷发射器·通用、鱼雷发射器·潜用；装甲·小型、装甲·中型、装甲·大型。无细分时只显示类别，不另加“细分：”行；后续各行仍为耐久、飞机燃油和详细修正。工厂列表、预览及悬浮共用此格式。中文中点两侧无空格、括号用全角；英文中点两侧各一个半角空格、括号用半角。消耗品只显示适用的类别和用途说明，不显示耐久或修正。未确定数值不以0或正常功能说明冒充已完成。
- 装备归属行沿用现有原版条件和通用排序规则。标题沿用原版颜色，不为装备自动套用核心稀有度。
- 适配评估读取实际舰种、类别和细分。装备存入仓库、取出或转赠保留耐久和飞机油量。
- 维修尚未设计，已禁用工作台合并修理、砂轮修理及铁砧双装备混修；单件铁砧改名保留。未来维修必须核对型号并显式恢复耐久，不得丢失或复制燃油。
