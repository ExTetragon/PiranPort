### 2.2 问题 1–10

| 编号 | 问题及影响 | 最终修复 |
|---|---|---|
| 1 | 空 `FluidStack.save` 抛异常，空桶/空伙伴可能无法保存 | 使用 `saveOptional`；每格实体独立持久化本格流体，空内容可正常保存。 |
| 2 | 放置后才读取已被消耗的物品；可能丢失最后一个桶的内容或覆盖邻桶 | 在 `applyImplicitComponents` 阶段恢复本格内容，再由 `setPlacedBy` 连接；移除物品类中的放置后恢复逻辑。 |
| 3 | 管道填充/抽取没有标记区块保存 | 储罐内容变化统一调用 `setChanged` 并更新比较器；模拟操作保持只读。 |
| 4 | 不同油品仍可配对，伙伴内容被逻辑主罐隐藏 | 配对前同时比较流体和组件；不兼容时保持各自独立。 |
| 5 | 矾土块、铝块、钢块没有正常掉落 | 补齐自身掉落；燃料桶采用正常战利品表并复制本格流体组件。 |
| 6 | 第三个桶改变邻接判断，旧配对和 64000 容量可能残留；拆除结算不完整 | 持久化明确伙伴坐标，第三格保持独立；加载、邻居和切轴时校验；玩家采集与非玩家移除分别结算。 |
| 7 | 管道缓存原 master 的裸储罐，拓扑变化后可能读写错误桶 | 每格提供固定身份的 `SharedHandler`，每次解析当前伙伴，并在连接变化时通知能力缓存失效。 |
| 8 | 比较器方法未声明方块支持输出 | 补齐 `hasAnalogOutputSignal`；按 `floor(15 × 存量 / 容量)` 输出，内容及容量变化时更新。 |
| 9 | 三种材料油湖同时注入全部含油群系，尝试次数叠加；地下半径错误 | 按群系分别选择砂岩/红砂岩/石头；独立地下配置使用半径 4–6，补齐群系过滤。 |
| 10 | 油湖可能覆盖容器、建筑或基岩，出现漏边和底部空层 | 先计算完整范围、整体预检，再统一写入；限定天然地形白名单，紧贴油体建底壳和侧壁，受保护或不密封时整次放弃。 |

## 3. 3.1 实施校正

以下规则记录当前代码的实际行为及与原设计的差异。它们不改写原始策划书，也不表示其他规划系统已经实现。后续修改规则时应同时更新本文、实现方案、测试清单及相关表格。

### 3.1 原设计差异

| 原策划书相关描述 | 当前实施规则 | 原因与影响 |
|---|---|---|
| 硝土掉落受时运影响 | 普通掉落 2–4 硝土，不受时运影响；精准采集掉自身 | 与当前掉落表及资源表一致，避免额外时运放大；矾土矿仍使用矿石时运。 |
| 单格燃料桶 64000 mB，按竖直组合描述 | 单格 32000 mB，同轴相邻两格逻辑共享 64000 mB，支持水平和竖直 | 每格独立保存，便于拆分、掉落和跨加载状态保持总量。 |

### 3.2 材料、加工与掉落

| 内容 | 当前规则 |
|---|---|
| 矾土矿 | 主世界采样 Y 0–128，每区块 9 次尝试，矿脉 size=9；普通掉落 1–3 矾土并受 `ore_drops` 时运影响，精准采集掉自身。 |
| 硝土块 | 主世界洞穴和下界生成；普通掉落 2–4 硝土，无时运加成；`1 硝土 + 1 木炭 → 2 火药`。 |
| 储存块 | 矾土、铝、钢支持 9:1 压缩与分解；正确工具挖掘掉自身；具备方块及物品通用标签。硝土压缩比例为 4:1。 |
| 矾土/矾土矿 | 熔炉 200 t，高炉 100 t；经验分别为 0.35、0.7。 |
| 钢锭/钢粒/钢块 | 分别由铁锭/铁粒/铁块高炉加工，耗时 100/12/900 t，经验 0.3。 |
| 原油桶加工 | 熔炉 200 t、高炉 100 t，得到燃油桶，经验 0.3；结果继承桶容器，不再额外返还空桶。 |
| 油桶作燃料 | 原油桶/燃油桶的熔炉燃烧时长为 4800/12000 t；高炉、烟熏炉按原版规则缩放，燃烧返还空桶。 |

高度范围描述采样原点，矿脉形状及自定义特征的偏移不保证每个最终方块都严格处于采样上下限内。生成次数、size 和稀有度均不保证最终成功方块数量。

### 3.3 燃料桶与流体守恒

- 同轴且沿该轴相邻的两格可配对；第三格不解散已有配对。两格内容的流体及数据组件必须兼容。
- 竖直组合以下方为 master；水平组合以先放置者为 master，同 tick 以坐标排序确定。master 决定分配顺序，每格仍各自保存流体。
- 填充先装 master，抽取先抽另一格。`SIMULATE` 不修改数据；实际变化标记保存并更新比较器，空/半满/满对应 0/7/15。
- 斧右键按 Y → X → Z → Y 切轴；先按 master 优先分配，再断开并根据新轴重新连接。
- 玩家采集时剩余桶优先填满到 32000 mB，超额由掉落桶保留。例如 40000 mB 拆除一格后，剩余桶 32000，掉落桶 8000。
- 非玩家移除仅断开关系，各格保留自己的份额，避免在战利品已经生成后再次搬油；创造模式不生成采集掉落，爆炸仍受原版战利品存活规则影响。
- 本格组件在放置物品被消耗前恢复。掉落复制不可变 `SimpleFluidContent`，保留流体元数据；空桶同样可保存。
- NBT 写入 `StorageVersion=2`，继续读取旧 `Fluid`、`PlaceOrder`。旧 master 中仍存在的 64000 mB 先完整保留，配对后分为两份；孤立超额只允许抽出，不再填充，不截断现有内容。此前已遗失的数据无法回填。
- 伙伴未加载时不强制加载区块，也不擅自搬移其流体。单侧卸载的完整运行验收仍待执行。
- 对外提供稳定的 NeoForge 流体能力代理。原版漏斗只能搬运桶物品，不能直接给没有物品槽的燃料桶灌油；真实第三方管道兼容性仍需手工验收。

原油/燃油的静止及流动态均为半透明，保留正常流体流动，不造成接触伤害，未附加点燃或火焰蔓延机制；它们不是已经实现的战斗系统状态效果。

### 3.4 油湖生成

| 群系 | 底部及侧壁材料 | 地表 | 地下 |
|---|---|---|---|
| 沙漠 | 砂岩 | 1/150 尝试，半径 4–8 | 1/50 尝试，半径 4–6 |
| 恶地系 | 红砂岩 | 1/150 尝试，半径 4–8 | 1/50 尝试，半径 4–6 |
| 热带草原系 | 石头 | 1/150 尝试，半径 4–8 | 1/50 尝试，半径 4–6 |

每类群系只引用对应材料的一种特征，不叠加三套尝试。地下采样 Y -32 至 16；安全检查可能放弃生成，实际成功数量低于尝试数量。

生成前计算完整油体、紧邻底面、连续侧壁及上方清理范围，再检查高度、可写边界和天然地形白名单 `piranport:oil_lake_replaceable`。遇到方块实体、容器、建筑材料、基岩、已有流体或无法密封的边缘时整次放弃；预检失败不残留局部写入。允许少量天然起伏，不强行挖穿山体。改动只影响新生成区块。

强制生成使用 configured feature 标识，例如：

```mcfunction
/place feature piranport:bauxite_ore
/place feature piranport:saltpeter_patch
/place feature piranport:oil_lake_sandstone
/place feature piranport:oil_lake_red_sandstone
/place feature piranport:oil_lake_stone
/place feature piranport:oil_lake_sandstone_underground
```

命令绕过 placed feature 的稀有度和群系放置过滤，仍会执行特征自身的安全检查，因此不能用它估算自然生成频率。
